FEEDBACK FROM PLAYTESTING:
- Make the number of taken colonists in the load colonists function configurable. Always reserve some minimal number of colonists on the source world, so that future population growth is not extremely slow.
- Make construction and repair consume antimatter.
- Report in the turn summary when owned unit finishes all orders and becomes idle (only once, no further reports if it stays idle).
- Show income and upkeep breakdown in the popup and in the info given to AI. Individual colonies with income and units with upkeep should be listed.
- Metal refinery should cost only a small amount of metal. Crystal refinery should cost only a small amount of crystal. The refinery components themselves should cost more credits.
- Unstable wormhole should cause the passing units to lose some antimatter.
- Owned planet should have some non-zero sensor range.
- Remove pulsar antimatter drain, since it makes the star completely useless for antimatter harvesting. Instead, add antimatter drain to some nebula or storm type.
- Black hole star type should double hyperdrive recharge time of units in its hex.
- Completely hide game graphics and GUI during AI enemy's turn, so the human player cannot see their units or bottom bar / sidebar info.
- Rename “Transfer Antimatter” context menu button to “Give Antimatter”. Rename corresponding function in the AI interface.
- Increase turret ranges of stationary defensive unit templates. Add more varied stationary defensive unit templates. Stationary units in general should have greater turret ranges than mobile units.
- Expand recon unit templates: add sensor ship unit template with advanced hyperdrive, so we have both basic and advanced hyperdrive sensor ship. We should also have at least 2 sensor ship template sizes (smaller and larger), and also smaller and larger sensor station. Reduce sensor ranges of other units (or perhaps remove sensors entirely from some units), to make dedicated sensor ships/stations more useful.
- Add current construction progress to turn summary.
- Add new section to AI memory: “Important events in previous turns”.
- Improve AI guidance for usage of different memory sections (strategy, objectives, commitments, beliefs…), and improve the differentiation of the sections, so the same content is not simply duplicated in different sections.
- Instruct AI to periodically trim outdated content of its memory.
- When a player no longer has any units or colonized bodies, a “Player has been defeated.” screen should appear. From that time, defeated player's turn should simply be skipped.
- Ensure that every generated system has at least one comet, one metal asteroid, and at least one colonizable body.
- Add a special "Nebula system" type, where all hexes will be of a new, special "Dense nebula" celestial body type. Dense nebula would feature limited short range and long range sensors (set all sensor ranges to 1/3 of normal values, round down to nearest integer for long-range sensors).
- Add new effects for Pulsar star type: limited short-range sensors inside the hex (1/3 of normal ranges), units in the hex should be hidden from long-range sensors, units will receive hull damage each turn.
- Split the loss section in human and AI turn summary into "Friendly and allied losses" and "Enemy losses".
- Include the unit owner in turn summary whenever a unit is mentioned in the combat or loss section.
- Add new order, valid for any ship with antimatter storage component: automatically resupply all friendly units in range.
- Reorganize and clean the strikecraft bay component sidebar GUI.
- Design and implement a way for ships to fire turrets and move at the same time, so pursuing ships won’t have to choose between moving or firing each turn, thus inevitably falling behind the escaping target. Perhaps the Attack order should calculate a fresh optimal move for pursuit each turn, make the move, then fire the turrets in the same turn (if the target is in range).
